# Resonance Bastion — authoritative browser-game design and implementation blueprint

Final authoritative implementation specification • working title: Resonance Bastion

## 1. Status, authority, and intended use

This document is the final authoritative specification for the browser-based autonomous fortress-defense game. It is self-contained: implementation must not depend on prior conversations, unseen documents, or historical versions. The project repository is named **Project Rando**. No existing game implementation is required by this specification; inspect the actual repository at implementation time without inferring mechanics from its name or contents.

Implement the stated rules and numerical values as the initial authoritative baseline. Centralize every tunable value so measured simulation and playtesting can revise balance without creating contradictory copies. A material change must be recorded in a decision log with the affected requirement, old and new behavior or value, reason, save/archive impact, and verification. A first playable increment is a development milestone, not a reduction of final scope.

The required product is playable in Android Chrome, with compatible browsers supported only after verification; uses polished raster 2.5D presentation with detailed 16-bit/32-bit-inspired pixel art; contains a permanent fortress and entirely autonomous combat; provides the complete specified tower, mobile-unit, support, trap, barrier, infrastructure, Warden, enemy and boss rosters; includes complete title, campaign creation, preparation, forecast, tutorial, battle, results, settings, accessibility and data-management experiences; and bundles original sound and music.

Music is presentation only. It never affects combat, encounter generation, randomness, input windows, cooldowns, difficulty or rewards. Muting music produces identical game events. There is no user-audio import. Fictional names such as Conductor, Iron Choir, Resonance Channel and Emergency Refrain describe the setting rather than rhythm mechanics.

Do not add multiplayer, global leaderboards, advertising, paid currency, energy timers, loot boxes, randomized equipment, crafting currencies, real-time construction waits, manual character control, runtime generative-AI calls, an APK requirement, or an account requirement.

### 1A. Requirement classes and authority map

“Must”, “required”, and unqualified mechanical rules are mandatory. Numerical gameplay values are the **initial tuning baseline**, not measured balance. A player option exists only where explicitly listed. Development diagnostics may expose full state only in a clearly labeled developer build; player inspectors obey perception. Performance, win-rate, economy and accessibility targets are **empirical acceptance criteria**, never claims that tests have passed. Optional platform capabilities have explicit fallbacks; optional does not make the roster, original audio or accessibility work optional.

One rule owner applies throughout: §3 state transitions/outcomes; §5 space and construction; §§7–11 catalog values; §24 shared simulation/generation contracts; §27 individual actions and growth; §25 economy/recovery; §26 controls/defaults; §19 persistence; §28 ongoing modes and bounds. Summary passages link to those owners. A local ability exception applies only to its named field; it never changes unrelated global rules. All cross-references use section numbers in this document.

### 1B. Terms and units

- **Bastion Architect**: the player. **Fortress**: persistent owned assets and layout. **Harmonic Core/Core**: immovable fortress objective; **Promotion Cores**: spendable currency, always labeled separately.
- **Asset/type/instance**: a friendly catalog definition versus one owned persistent identity. **UUID** is a unique persistent identifier; a **simulation entity ID** is a deterministic run-local integer. A squad’s visual members are one entity. **Operational** means body durability above zero and not disabled for the action in question. **Wreck/incapacitated** means mechanical/biological body durability zero, retaining ownership.
- **H / I / body durability / HP**: biological Health / mechanical Integrity / either / generic hit points. Shields are separate finite pools. **Armor** reduces body damage, not shield absorption. **C**: Command Capacity; **R**: range; **S**: movement speed; **CD**: cooldown; **DPS**: damage per combat second; **LOS**: line of sight; **AoE**: area of effect; **GU**: ground unit, one logical cell edge. **G/A/B** target layers mean ground/air/both. Underground is an untargetable movement state, not an extra attack layer.
- **Rank** is Bastion Rank 1–100; enemy **rank variant** is Common/Veteran/Elite/Apex. **Band b** is an encounter strength band 1–20. **L/E/★** are asset Level, Enhancement tier and promotion stars. **TP** is Threat Points; internal **qTP** is integer quarter-TP, 4 qTP=1 TP. **Doctrine** inventory grant, **Warden doctrine preference**, and **specialization branch** are distinct choices.
- **Combat time/simulation time** are the same 60-tick-per-second clock, frozen on pause. **Director time** advances only when deployment is not held and combat is running. **Real interface time** is monotonic foreground time for captions/menus/audio, independent of speed; it freezes for hidden pages. Wall-clock dates label saves only. Unqualified gameplay seconds, rates, timers and windows use combat time; deployment schedules/warnings use director time; UI/audio exceptions explicitly say real time.
- **Plan**: validated immutable deployments and rules. **Packet**: one atomic group of at most six deployments. **Descendant reservation**: capacity/TP owned by a future child, transferred once at creation. **Run**: one attempt with an identity independent of its seed. **Receipt**: immutable result/transaction evidence. **Checkpoint**: recoverable start state, not approximate mid-battle serialization. **Archive Replay** starts a new run with current army; **Checkpoint Trial** is a no-reward clone.
- **Authority state** means simulation/persistence data; render sprites, animations, sounds and UI are views of it. **RNG/PRNG** means seeded pseudorandom-number generation. **Fixed point** means integer multiples of a declared unit. **CSS px** means browser layout pixels, distinct from raster source pixels; **DPR** is device pixel ratio; **FPS** frames per real second; **MiB** = 1,048,576 bytes.

## 2. Product definition and non-negotiable boundaries

Campaign stages use authored encounter plans. Expeditions and other generated modes use deterministic seeds, encounter recipes and versioned generators. Siege Archive stores compiled plans and records. Wave-pressure graphs describe planned hostile deployments, not music. Boss phases use explicit health and state transitions with bounded transition time. Simulation speed is independent of soundtrack playback. The Harmonic Core is a fictional fortress objective, not an audio-analysis device.

## 3. Core experience and state machine

The Bastion Architect prepares a fortress, chooses a siege, reviews reconnaissance, deploys one Warden, configures policies, and starts autonomous combat. Preparation is the source of agency. Results explain what succeeded and failed and support a meaningful next improvement.

Primary flow: Boot → Title → Slot Selection → Campaign Creation or validated Load → Preparation → Forecast → Preflight → Siege → Cleanup → Results Pending → Results → Preparation. Pause and recovery are explicit overlays/states as below. Tutorial uses real systems; Calibration and tutorial practice use disposable clones.

Preparation permits build, move, rotate, store, sell, repair, heal, restore, enhance, promote, respec, name, select Warden, configure policies and choose siege. Beginning combat locks all state-changing tactical actions, including gates, anchors and loadouts. Battle permits camera, inspection, overlays, accessibility, audio settings, pause and speed. A surrender button is present in Pause and requires a second confirmation; it finalizes defeat, damage and earned rewards. An interruption restart is different from surrender and restores the pre-siege checkpoint without rewards.

Victory requires a live Core, no scheduled deployment, and zero live enemies, including Carrier children and boss summons/subentities. Enemy projectiles already in flight resolve before victory; require 1 simulation second without any damaging hostile entity or projectile. Defeat becomes irrevocable when Core current Integrity reaches 0 during damage resolution; finish that tick’s damage/death bookkeeping, then freeze the outcome before healing can revive it. Inevitable Defeat is declared after 3 continuous combat seconds only if no operational friendly damaging weapon/trap, no potentially damaging in-flight friendly projectile and no scheduled friendly damaging effect remains, while a live hostile can damage Core. Support cannot revive incapacitated assets. Otherwise use stalemate diagnostics; range, stealth, temporary obstruction or predicted DPS alone never proves defeat.

When every scheduled deployment has actually occurred, enter Cleanup. No new scheduled waves; previously budgeted carrier/boss summons may still occur. No reward reduction or artificial enrage. A stalemate diagnostic after 30 simulation seconds without damage or meaningful movement requests route recovery; after 90 seconds, pause and offer Restart From Checkpoint or Surrender. Never silently grant victory, delete an enemy or teleport it through a wall.

### 3B. Terminal precedence and stalemate

At each tick end evaluate, in order: (1) Core-zero defeat; (2) confirmed surrender at a paused tick boundary; (3) three-second inevitable-defeat condition; (4) victory; (5) stalemate pause. Once terminal, subsequent UI or queued events cannot change that result. Simultaneous Core/final-hostile death is defeat. On terminal defeat cancel all future unexecuted actions and record damage only through the terminal tick; no post-result projectile damage.

Victory requires live Core, empty ordinary deployment queue, no living hostile body, no reserved/queued child or unresolved spawn obligation, and no hostile damaging projectile/independent delayed effect. Then count 60 consecutive combat ticks without hostile damage potential. Cancel unused reservations of dead summoners per §24D before this test. Attackless living prisms/roots/decoys count as specified; decoys vanish with their boss. Friendly projectiles may expire without delaying victory if no hostile remains. No hostile mine type exists in the catalog.

For inevitable defeat, a temporary jam, root, overheat, cooldown, depleted but rearmeable trap, pending living-owner signature or temporarily missing target is not loss of damage capability. Potential hostile Core damage must be physically achievable through open or destructibly breachable space; a lone Mender is not sufficient. Remaining noncombat hostiles invoke recovery, never an invented attack or automatic win. Meaningful movement for stalemate means progress of at least 0.15 GU toward an active reachable goal within two seconds, not circling/pairwise jitter; scheduled packets or bounded effects due within 30 seconds suppress the diagnostic until due. The 90-second pause always offers checkpoint restart and surrender, so even a player-chosen incapable layout remains recoverable.

## 4. Browser and project architecture

Implementation baseline: TypeScript, Phaser free framework, Vite, semantic HTML/CSS interface over a game canvas, IndexedDB, Web Audio, optional service worker; unit/scenario tests with a free test runner and browser checks with Playwright where executable. Pin exact dependencies and lock file after an environment smoke test. Do not assume Phaser 3 APIs apply unchanged to Phaser 4. Use the installed version's official documentation. Rendering engine choice is confirmed by a mobile-oriented projection/input/context-loss smoke test before content expansion.

Keep simulation independent of Phaser: deterministic movement, targeting, cooldown, collision, damage, wave scheduling, reward and save modules must run headlessly. Canvas is presentation, not authoritative state. DOM buttons/dialogs have accessible names and normal keyboard navigation. No gameplay based on CSS animation completion or audio callbacks. Custom collision and navigation handle entities; avoid unnecessary rigid-body simulation.

Suggested modules: app/bootstrap; sim/{world, clock, combat, collision, perception, ai, navigation, encounters, rewards}; data/{assets, enemies, bosses, progression, campaign}; render/{projection, world, animation, effects}; ui/{title, base, forecast, hud, results, settings, tutorial}; persistence/{database, migrations, backup, transactions}; audio/{mixer, synth, score}; tests/{scenarios, invariants, browser}; assets/{atlases, icons, music, sfx}; docs/{blueprint, decisions, status, test-evidence}.

Ship a static production build. The production game must bundle required scripts, fonts, artwork, score definitions and audio; no runtime CDN, tracking, external asset lookup or AI calls. Serve over HTTPS on a stable origin; local developer testing uses a supported localhost server. A downloaded HTML file is not the authoritative delivery path. Hosting is a separate environment check: do not promise permanent free hosting, a published URL, or offline support until tested. No account is required to play. If a provided hosting tool is used, follow its actual workflow and report any blocked publication dependency.

Chrome Android is the primary validation target; Edge/Samsung Internet/Firefox Android are secondary candidates, not automatically certified. Safari/iOS and desktop Chromium/Firefox/WebKit are additional checks. Require JavaScript, canvas renderer, Pointer Events, IndexedDB for retained progress and Web Audio for sound. If storage fails, offer clearly labeled Temporary Session plus backup export; never show a false Saved state. If audio is unavailable, gameplay remains functional with captions. If no verified renderer initializes, show a readable compatibility page.

On hidden tab, page freeze, lock screen, orientation change requiring reflow, or WebGL context loss: pause simulation and sound, show Resume after recovery, and never advance through wall-clock absence. No offline reward accumulation. Handle renderer restoration from authoritative world state. Resize only changes presentation. Optional home-screen installation must never be required.

## 5. Coordinates, projection, field and placement

One ground unit (GU) equals one logical cell edge. All ranges, footprints, movement speeds and areas use GU, not screen pixels. Simulation uses x east, y south; cells indexed 0–59. World bounds [0, 60) × [0, 60). Enemy staging perimeter: cells with x<6, x ≥54, y<6 or y ≥54, permanently unbuildable. Final interior is [6, 54)² = 48×48 cells. Initial build region [12, 48)² = 36×36.

Expand north [12, 48)×[6, 12) at Rank 15; east [48, 54)×[12, 48) at 40; south [12, 48)×[48, 54) at 60; west [6, 12)×[12, 48) at 80. Unlock northwest corner at 85, northeast 88, southeast 92, southwest 95; each is 6×6. Costs respectively 2000, 6000, 12000, 20000; corners 8000 each. Rank enables purchase; a corner also requires its two adjoining purchased cardinal regions; no timed construction. Every added region has new ground artwork but unchanged GU scale.

Core precinct [27, 33)² reserved. Core physical footprint [28, 32)², center(30, 30), immovable, Integrity 10000, Armor 20. Friendly deployment pad [29, 31)×[33, 35) reserved. All legal entrances are six fixed 2-cell entrance markers with at least3 GU clear staging width, centered exactly at (3,18), (3,42), (18,3), (42,3), (57,30), (30,57), numbered 1–6 in that order. Spawn pads must allow largest enemy radius; display their numbered icons. Core attack goals are legal cells adjacent to its collision footprint, not its center.

Projection uses 64×32 source diamond tiles and 32×16 projected cells: let dx=x−cameraX, dy=y−cameraY; camera rotations 0/90/180/270 map these to (u,v)=(dx,dy)/(−dy,dx)/(−dx,−dy)/(dy,−dx). screenX=originX+16×zoom×(u−v); screenY=originY+8×zoom×(u+v)−24×zoom×visualHeight. For ground placement set visualHeight=0, X=(screenX−originX)/zoom and Y=(screenY−originY)/zoom, then u=X/32+Y/16, v=Y/16−X/32; invert the selected rotation and add camera position. Ground east/south project along the diamond edges; the compass shows actual projected world north. This is raster 2.5D, not a true 3D camera. Four camera orientations change neither ranges nor collision. Camera rotation is available in preparation and battle under §26, with no unlock requirement. Sprite selection uses its declared foot anchor/body identity; clicking high artwork does not shift placement coordinates.

Zoom 0.35–2.5; default 1; Fit calculates bounding-box fit inside unobscured play area, permitting values below 0.35 for whole-field view only. Strategic at<0.65, tactical 0.65–1.35, close>1.35. Objects depth-sort by projected ground foot position then stable entity ID; height is a separate sprite stack, not a changed hit point. Fade obstructing structures to 35% opacity when hiding selected unit/Core/Warden; preserve perimeter outline. Selected object list provides access to overlapping objects. Contact shadows are baked/cheap decals, no mandatory dynamic lighting.

Placement snaps centers/footprints to integer cell bounds. Display ghost footprint, price, capacity, rotation and exact invalid reason. Commit only on explicit Place under §26; ordinary selection taps and dragging the camera cannot purchase. Rectangular occupancy rotates by 90°; 45° is allowed for turret facing, visual direction and supported symmetric objects only, never ambiguous diagonal grid occupancy. Traps occupy their ground cell; an Elevated Platform is the only explicit stacked occupancy exception. Low cover and channels cannot stack with traps.

Ranks 1–24 require radius 0.45 and radius 0.75 ground routes from every legal ground entrance to a Core-adjacent goal; additionally require radius 1.2 where the selected plan includes a ground boss. No diagonal corner cutting. Before rank 25 gates must remain open for enemies as well as allies if needed for the route. At Rank 25 Fortified Closure permits sealing routes only with the selected plan’s validated breach capability (§5A). Generation never examines the layout; preflight verifies the already compiled plan and forecasts its available breachers. Structures are destructible; no layout can permanently isolate an objective behind indestructible gameplay walls.

Move/rotate/store free. Storage preserves identity, damage and all investment. All reversible asset/layout/economy preparation edits are atomic commands with Undo/Redo until leaving the base or beginning siege. Global settings, slot deletion/import, first-claim ledgers and result commits are outside asset Undo/Redo; their dedicated confirmations/recovery apply. Undo restores exact wallet/assets rather than executing sell refunds. New edits clear redo. Presets:5 per slot, record IDs, placement, rotations, gate policies, sectors and tactics. Validate entire load before commit; missing sold assets are reported, never recreated. Provide an explicit partial-load confirmation with preview if user chooses it.

`visualHeight` is presentation-only elevation in GU-equivalent art units: ground foot anchors 0, ordinary flying bodies 1, Shatterstorm 2. Sprite height inside a frame already depicts building/body volume and is not added again. Mounted tower uses the platform’s declared 0.5 visual elevation; collapse lowers it cosmetically without changing range/collision rules. Depth/picking retain ground foot identity; airborne shadows stay at ground projection. These art elevations never create projectile immunity or a third collision layer.

### 5A. Exact geometry, occupancy and legal routes

Cell (i,j) is [i,i+1)×[j,j+1); build rectangles use integer top-left coordinates and their catalog dimensions. A circle may touch but not penetrate a solid boundary; standing at world maximum is outside. A footprint is legal only if wholly on purchased land, outside precinct/pad, disjoint from other deployment footprints, and within all allowances. The Core is the only precinct structure. Selected Warden alone may use the reserved 2×2 deployment pad; if that pad is not used it stays empty. Mobile deployment reservations cease being obstacles at tick 0; they resume as layout reservations after results. Ground mobile movement may cross friendly traps, Low Cover, Razor Field, Channel and empty unmounted Platform; buildings/walls and a mounted tower are solid. Air movement ignores ground occupancy, but not air bodies/bounds. Wreck placement retains ownership occupancy for construction; its combat debris is traversable. A restored Platform with an overlapping compatible tower may be explicitly mounted as one atomic preparation action. An already collapsed platform/tower pair may retain their shared footprint as the sole inert stack exception while the platform is a wreck; it grants no mount bonus until explicitly restored/remounted. No other duplicate occupancy is legal.

For routes inflate solid footprints by the tested radius; validate continuous clearance along every graph edge, including diagonals, not only at cell centers. Melee movement goals stop within range of the target boundary without entering it. The unpurchased interior is navigable hostile/friendly terrain but unbuildable; expansion never creates new collision. Each entrance’s staging zone is the 4×4 square centered at its marker, clipped only to world bounds. Deployment uses free half-cell centers sorted by squared distance to marker, then y,x; clearance covers the full body. The marker width is an icon, not a gate aperture.

Default construction validation always preserves the 0.75 GU route profile before Rank 25, and validates ground-friendly paths from deployments to primary/secondary anchors using their actual radii. A boss forecast additionally validates radius 1.2. Storing walls cannot strand units; moving a group validates without its original occupancies but commits the whole replacement simultaneously. Mobile deployment blockers never serve as permanent route walls.

After Fortified Closure, a sealed layout is legal only if a deterministic breach-cost search from each used ground entrance to a Core attack goal succeeds using the plan’s ground damaging entities. Every used ground front must have a breach-capable damaging role, or a documented accessible meeting route to another such front. A supporting-only front may join that route; an isolated supporting-only pocket fails. Sapper/Breaker/boss breachers use their contracts; Runner/Raider/Bulwark/Veil/Mole/Carrier/Harvester can strike blocking destructible assets with their normal melee attack. Lancer/Jammer/Herald/Drainer can target a blocking destructible asset with their ordinary weapon when LOS/range permits. Bombard needs a legal firing position respecting min range. Mender/prisms/decoys cannot breach. Forecast reports the actual capability; never add enemies after the layout is seen. Temporary body congestion is handled by movement/holds, not baked into static reachability.

Mole/burrowed Root may cross destructible ground footprints underground but not world bounds or the precinct enlarged by 3 GU: forbidden underground rectangle [24,36)². If beginning burrow in that exclusion, decline burrow and fight surfaced. Surfacing requires a free collision-legal point; search nearest half-cell positions then remain in an outward travel state until one exists. Never attack underground; the surface warning lasts 1.5 combat seconds before any attack. Detector-forced surface uses the same legal-point search and grace. Transition waiting still obeys the visible 90-second recovery pause.

Camera Fit includes the projected field and maximum sprite-height padding inside the unobscured rectangle, centered on its bounds. Pan allows every world edge and tall sprite to be centered; no clamping that traps the Core behind a sheet. Fit views may use icons because world artwork cannot remain individually readable on a 60×60 field at 360 CSS px. Full-size named lists and Jump/Zoom are always available. Depth key is rotated ground v+u, then rotated lateral u−v, then entity ID; draw a mounted stack with platform beneath tower and pick in reverse visible order. Solid telegraphs always render above terrain with occlusion outlines. Inverse projection uses ground height zero; sprite picking uses the declared body mask/foot anchor plus named overlap picker.

Low-cover protection tests whether the segment from attacker to target intersects that cover’s footprint before reaching the target and whether target boundary is within 0.6 GU of the far edge. Terrain traversal uses the slowest overlapping terrain speed factor (debris 1/1.15, cover/ordinary-through-obstacle 0.8), then strongest status slow, then Channel 1.15 friendly/0.90 hostile. Root forces movement zero. Navigation costs use reciprocal terrain/channel speed; combat slows do not rebuild topology. No multiplicative duplicate terrain slowdown from multiple debris decals.

## 6. Simulation and combat rules

Fixed simulation 60 ticks/sec; interpolate rendering. All durations convert to integer ticks, GU positions quantized to 1/1024; seeded streams and stable tie-breaking under §24A. Cosmetic randomness cannot alter simulation. Maximum 12 ticks/render; overload detection and visible recovery follow §24A, with no skipped ticks. Identical compiled plans + normalized starting world + simulation/content/policy versions + tactical inputs produce identical headless outcomes; do not promise cross-version exact replay. Attack intervals round to nearest tick.

Distance uses ground Euclidean center distance minus target collision radius for circular mobile targets; stationary targets use closest distance from the source center to their occupied rectangle, as clarified in §27A. Units radius 0.35, heavy 0.6, Warden 0.45, ordinary enemy 0.35, heavy 0.65, boss 1.2 unless table override. LOS segment intersects blocking footprints; mobile units and low cover do not block LOS. Closed walls/gates and all operational tower/building footprints block direct shots; own footprint/mount launch exclusions follow §24A. High platform shots ignore low cover only; they do not shoot through walls. Arcing mortar ignores LOS but respects min/max range and visible detected targeting.

Armor formula: effective Armor=max(0, armor−flat Shred)×(1−penetration); damage=raw ×100/(100+effective Armor)× resistance × cover × (1−strongest applicable reduction) × (1+strongest vulnerability). Penetration clamps 0–1. Round authoritative body/shield changes to 1/1024 points at the defined fixed-point boundaries in §24A; presentation rounding never feeds back. Resistances below 0.5 disallowed for ordinary content; no elemental damage immunity. Front shields absorb before body; shields do not use armor. Ordinary shield hits spill residual raw damage through normal body mitigation when a shield is depleted; attacks with an explicitly stated no-overflow tag discard the residual instead. Front arc 120°; attacks from outside bypass. Max allied reduction 40%; max boss reduction 35%; finite shields are separate pools. No friendly fire. No critical hits in baseline; no hidden crit gear.

Accuracy is probability of intended-hit aim; misses offset aim deterministically 1–2 GU but may hit another legal hostile. Melee, beams and chain arcs cannot randomly miss. Direct bullet travels at stated speed, swept collision prevents tunneling, dies on first solid collision or max range+2 GU. Non piercing bullets intercept first enemy on lane. Ordinary projectiles do not retarget in flight; guided Skyguard missile turns at 180°/sec. Air collisions use air layer; mixed-target projectiles lock layer on launch. Screen effects never affect collision. Attack cooldown starts on release; target loss before release cancels warmup without consuming cooldown.

Default weapon warmup 0.1 s; turret rotation 180°/sec, mobile aim 360°/sec, big artillery 90°/sec. Need aim error ≤8° to release. Explosive AoE does full damage within inner half-radius, falls linearly to 50% at edge, once per target. Overlapping explosions are independent. Beam ticks 0.1 s; damage output specified per second. Burn uses 50% penetration, lasts 4 s and has at most 3 stacks; refresh and source attribution follow §24A. Slow effects use strongest only, cap 50% reduction; bosses cap 25%. Root max 2 s ordinary, 0.5 s bosses; after root ends 4 s root immunity. Vulnerability bonuses strongest only, cap 25%. Armor shred strongest flat amount only unless explicitly cumulative; cap 50. No generic knockback unless an ability defines it.

Cover: eligible biological ground unit within 0.6 GU behind low cover relative to attacker receives 20% direct ranged reduction; explosive and beam attacks ignore it. Stealth hidden beyond 2 GU absent detection; firing reveals for 2 s; revealed at detector radius or within 2 GU; silhouettes and enemy counts may show approximate stealth contacts after forecast, not targetable coordinates. Burrowed units untargetable but cannot attack underground; must surface at least 3 GU outside Core precinct for 1.5 s before attack. Detection can force surface. Shields, buffs, status durations and damage have visible explanations.

Mobile bodies block softly within same team; opposing ground bodies separate physically. Squad is one collision/AI/persistence entity with visual members, not multiple damage engines. The six mobile squad assets apply the injury-output rule clarified in §27A; Warden output does not decline with health. Display this rule. Biological assets at 0 become incapacitated; mechanical at 0 become wrecks. Neither can be revived mid-siege in baseline. Destruction clears tall collision and produces traversable debris with 1.15 movement cost. Repairs/heals cannot affect 0-health assets. Finite-charge traps expend stock; rechargeable fields retain their documented behavior; infrastructure never creates persistent extra squads during battle.

Warnings derive from authoritative events: Core crosses below 50%/25%; Warden below 30%/incapacitated; friendly asset wrecked; enemy breaches inner 6 GU; entrance activates; boss warning/phase; stealth contacts; key support jammed; traps depleted; route recovery; results/save failure. Threshold alerts fire on downward crossing, re-arm only after health rises 10 percentage points above that threshold. First breach groups repeat enemies in the same sector within 10 combat seconds; details keep all events. Only alert “support jammed” for assets actually suppressed. Do not invent a lane-integrity percentage or a predictive “defeat imminent” bar.

Critical condition banner remains until resolved/acknowledged; acknowledgment hides its large presentation, not its persistent badge or event. Ordinary caption persists 6 real seconds, informational caption 4, adjustable to Persistent Until Dismissed; this is separate from simulation-time warning duration. Boss countdown uses combat time for an attack, director time for arrival; arrival countdown explicitly says “Deployment paused” during Population Hold. Max two nonmodal captions; merge duplicates, queue up to 10, retain overflow in history rather than silently discard critical information. Never animate rapid flashing. Do not announce every tick/damage number to screen readers: announce meaningful grouped status changes using appropriate live status regions without stealing focus.

Optional auto-pause for Core critical, Warden incapacitation, boss arrival or first breach is Off by default. If enabled, trigger once per condition crossing/event, latch until condition resolves; Resume does not instantly pause again. Triggering auto-pause changes no units, damage or rewards. Menus that cover most of the world pause battle; compact read-only inspector does not by default. A modal may resume only a battle it paused, and only when no other pause reason remains; manual pause, hidden tab or context-loss pause always requires explicit Resume. Pressing Pause while a modal is open still records manual pause.

Do not deliver a fortress composed primarily of plain geometric primitives or flat vector icons. The required baseline is late-16-bit readability with early-32-bit sprite detail, layered backgrounds and fuller animation, expressed through one coherent art language across the entire game.

Palette: retain the main UI/faction colors, then define 4–6-tone material ramps with intentional highlights and shadows. ### Original asset creation and approval pipeline

1. Create a style sheet specifying pixel density, palette ramps, lighting, projection, outlines and frame bounds. Produce an original art proof containing one Sentry, Rifle squad, Warden, Runner, barrier section, Core fragment and terrain transition at actual gameplay scale.
2. Inspect that proof at ordinary Android scale and close zoom before mass-producing assets. The user directs the aesthetic; approval of one look is not permission to mix unrelated art styles later.
3. Use image generation when available for original visual development, portraits, key art and candidate sprite designs. Inspect its outputs before adopting them. A generated image is not automatically pixel-perfect art, an aligned animation sheet or a ready-made transparent sprite.
4. Reconstruct/clean approved candidates as raster pixel assets using appropriate available tools. Image edits use the image-generation tool unless the user explicitly requests a different editing route. Newly coded procedural raster assets are acceptable only when their actual result meets the approved pixel-art style. Export PNG source frames and consistent runtime atlases; preserve editable source and palette definitions.
5. Build and verify animations with stable pivots, frame dimensions, perspective, anatomy and equipment. Do not independently generate every animation frame and accept character drift. Validate transparency, seams, tile edges, atlas padding and browser rendering.
6. Record origin/tool, source parameters where relevant, license for any third-party tooling/fonts, dimensions, pivot, collision footprint, frame sequence, states and review status. No external asset pack is required.

Temporary geometry is allowed in explicitly labeled construction/combat prototypes. It cannot satisfy final-art acceptance. Include the early art proof within Gate 1, before large-scale roster production; final polish is Gate 7. Do not call a prototype visually finished merely because it functions.

### 19A. Durable commands, results, fences and bounded exports

The authoritative campaign is the latest validated committed snapshot plus its non-restorable claim/writer fence and, when present, active run checkpoint or immutable pending result. The in-memory world is authoritative only while an uninterrupted battle is running; it cannot silently replace campaign progress. Keep current and previous validated snapshots separately; “previous” updates only on successful campaign command/result commits, never on a failed write. A transaction includes the command’s before/after revisions and validation; Undo is a new atomic write of the prior exact state, not a refund calculation. Reset Undo/Redo at any mode departure, campaign switch, reconstruction subsidy, result commit or import.

Preflight allocates sequence n from a monotonically increasing counter in the same transaction that stores the checkpoint, compiled plan hash, frozen reward coefficients, claim eligibility, initial stats and writer revision. There is one active campaign run. Restarting an uninterrupted or interrupted attempt reuses that active sequence and checkpoint until the player abandons/finalizes it; Restart can never create a rewardable copy. Abandon marks the sequence skipped and advances finalized watermark before another allocation. Surrender on a live world builds a defeat result from its actual terminal state; an interrupted run cannot pretend unknown partial kills survived.

At terminal tick construct immutable PendingResult `{runID, baseRevision, planHash, terminalTick, outcome, endBodyAndStock, aggregates, rewardOriginBuckets, economyPolicyID, rewards, claims, checksum}`. Step 1 journals this object with active checkpoint untouched. Step 2 in one readwrite transaction checks writer generation, base revision, runID and fence, applies body/stock, wallet, XP, ownership unlocks and claims, writes the receipt, advances watermark and removes active/pending state. If Step 1 fails, retain result in memory, pause and offer Retry/Export Pending Recovery; browser closure then recovers only the last durable checkpoint, not a fictional unrecorded result. If Step 1 succeeds and Step 2 fails, reopen loads that same pending object and retries it. If Step 2 succeeded but its acknowledgment was lost, receipt/fence read proves committed and opens Results without applying again. Exports include the exact journal and base needed to retry; pending imports must pass baseRevision/hash checks. No persistent result can be partially paid.

Endurance block commit stores a compact exact next-block start: body durability, permanent/temporary stock as applicable, signatures, frozen levels, participant/contribution sums, destroyed-qTP totals by reward-origin block/segment, completed entitlement and plan cursor. This is a clean boundary without surviving enemies/projectiles/statuses, not a mid-block approximation. Persisting block damage updates the active run’s baseRevision to the committed block revision and does not expose editable Preparation. If storage fails between blocks, stop before the next starts. Finalization marks every block entitlement consumed by the one final run receipt. Restart Checkpoint means current incomplete block in Endurance; ordinary battles mean siege start.

Store claim fences in the same IndexedDB database/transaction as results: last allocated/finalized sequence, at most one active run, 16 recent receipts, finite campaign (40), fixed mastery (12), role (16), boss (8) and campaign milestone claims, plus at most 4096 generated first-success hashes. Restore Previous combines the selected snapshot with the maximum local watermark and union of finite claim sets; it does not restore wallet from the fence or merge wallet values. Recalculate claim presentation accordingly. Stale snapshot active runs at/below fence become abandoned recovery-to-preparation, not payable pending receipts. Same-ID import cannot lower local fences; conflicting pending results are rejected until resolved. Imported different-ID campaigns replace only explicitly selected slots, never merge ownership. Deleting a campaign removes its local progress after confirmation; later deliberate backup import is restoration, not an anti-cheat guarantee.

Writer ownership uses `{tabID,generation,leaseExpiry}`. Heartbeat every 5 real seconds, expiry after 20; use Web Locks when available and this record in all write transactions. Take Over atomically increments generation after confirmation, even when the old tab appears asleep; stale writer transactions compare generation and campaign revision inside the same transaction and abort. Returning hidden tabs reacquire/check before any write or Resume. Frozen tabs may miss heartbeats; expiry grants eligibility for takeover, never permission for two writers. A second tab is read-only and may export last committed data. Blocked database upgrades show Close Other Tabs/Retry and never delete the database to recover. Unexpected close/transaction timeout (10 real seconds) is a recoverable error; reopen and inspect receipt before retry, never assume timeout means commit failed.

Import validation is all-or-nothing before replacing any selected slot: 32 MiB UTF-8 maximum, maximum nesting 32, bounded collections below, plain JSON object types, no duplicate keys, no prototype-bearing merge, integer/rational domain checks, UUID/content references, derived-stat/XP consistency, investment ledgers, valid footprints/overlap/land, legal mode checkpoints, finite clocks/stream states, checksums and supported versions. Unknown newer schemas/content remain untouched. Migrations operate on an isolated copy, validate fully and commit atomically with original retained. Precompute hashes/migrations outside an IndexedDB transaction; do not await unrelated network/timers inside an active transaction. Write-probe storage independently of renderer/audio, then handle later quota/eviction errors too.

Temporary Session is an explicitly labeled in-memory campaign with the same transaction validation and local receipts, export/import available, no Saved claim. Closing loses unexported state. Do not silently convert an existing retained campaign to temporary mode or pretend two-tab conflicts are storage absence. If sound fails, only audio degrades; if persistence fails mid-battle, its committed start checkpoint remains recovery source and pending results can be exported in memory. Backups include all indispensable logical state and optional global preferences; player chooses whether to apply those preferences on import. Android download/share fallbacks use feature detection; successful export means bytes offered successfully, not proof the player has stored a durable external copy.

Per slot limits: 1024 owned assets; 5 presets; 100 detailed results; 50 favorite and 50 nonfavorite archive plans; 20 anti-repeat fingerprints; 64 comparison buckets; 1 Long Watch series with 3 unstarted offers; 1 active/pending run; 16 recent receipts; 4096 generated bonus hashes. Current active/favorite plans cannot be evicted automatically; pruning nonfavorites uses last-used order then hash and gives notice. Records hold at most 200 event summaries, a 10-second-binned timeline of at most 180 bins with deterministic adjacent-bin compaction, 36 heatmap bins, and aggregate per-type/asset performance. Exact aggregate reward/contribution counters are retained even if detail is pruned. Heatmap has 6×6 bins, each representing 10×10 GU. Production does not retain an unbounded per-hit log; optional headless developer runs may stream full logs to external test artifacts.

A compiled ordinary plan is ≤256 KiB canonical JSON; Endurance’s complete six-block plan ≤1 MiB; one indispensable slot core (assets, claims, active checkpoint and pending results, excluding optional histories/archives) ≤8 MiB. Rejection happens during plan preparation/import with a readable error, not during result commitment. Export measures actual serialized bytes; multi-slot exports that exceed 32 MiB offer per-slot files and explicit optional-history omission, never remove active run/claims. Every maximum-shaped valid indispensable slot must pass a roundtrip export fixture. Hash-based encounter codes ≤16 KiB encode only generation inputs, never ownership; legacy archived plans requiring old compiled data use a plan export ≤1 MiB. Validate each separately from campaign backups.

## 24. Combat, ownership and encounter contracts

The rules in this section are authoritative implementation contracts. They close combat, ownership and encounter edge cases without claiming that untested balance values are proven. Preserve the complete roster and presentation requirements.

### 24A. Tick order, numeric semantics and attacks

At 4× speed and 30 FPS, eight 60 Hz simulation ticks are required per rendered frame. Use a maximum of 12 ticks per render, with an 8 ms simulation-work budget as a profiling target, not an instruction to skip ticks. Retain unprocessed simulation time. If backlog exceeds 0.5 combat seconds for 2 real seconds, auto-pause with “Simulation cannot keep up—try a lower speed”; explicit Resume resets the wall-time accumulator, not gameplay state. Do not claim achieved 4× unless observed tick throughput supports it. A hidden tab accrues no backlog. Test 30/60 FPS with every speed.

Tick order is fixed: (1) expire statuses whose endTick is this tick and apply scheduled topology changes; (2) advance eligible director clock and release due deployment packets; (3) perception/AI decisions due this tick, using a snapshot; (4) movement/avoidance and facing; (5) finish valid attack/ability windups and collect releases; (6) advance projectiles and collect swept impacts, area hits, beam and damage-over-time ticks; (7) process damage and shields in (impactFraction, sourceID, releaseSequence, targetID) order; (8) resolve deaths/incapacitation and schedule death children for the next tick; (9) apply healing to surviving recipients; (10) phase/trigger bookkeeping, reward contributions and outcome checks. Events scheduled after their phase execute next tick. Released projectiles remain valid after their shooter dies. Unreleased attacks cancel if the source dies. If Core and final enemy die in the same tick, defeat wins. Healing cannot revive a target killed in damage resolution.

Maintain integer tick timers; normal timed effects are active on [startTick,endTick). Continuous output accumulates fixed-point fractional carry and applies damage/healing on its defined 0.1 s weapon or 0.25 s support ticks; do not independently round tiny pulses to zero. Currency rounds only at the stated final step; positive half ties round upward. Internally use nonnegative finite health/armor/output and clamp health to max; validate overflow bounds. Missing data is an error, not an implicit zero-stat asset.

Damage tags: Kinetic, Explosive, Energy, Burn; ordinary resistance multiplier is 1 for all existing assets/enemies. Tags organize effects and documented exceptions; no unlisted elemental resistance wheel. Vulnerability uses multiplier 1+strongest vulnerability. Cover and strongest non-shield reduction multiply separately. Percentage reduction value d becomes multiplier 1−d in the damage formula. Ordinary allied damage reduction is strongest applicable effect, capped 40%; Holdfast 20% does not add to Barracks 10%. Dash reduction uses that same cap. Burning armor penetration is 50%; burn bypasses neither shields nor other mitigation. Armor changes cannot reduce effective Armor below zero. Structure bonuses only exist where listed; Reinforced Wall alone does not secretly cause extra incoming siege damage.

Default projectiles: radius 0.05 GU kinetic, 0.1 shell/missile; instant effects have no projectile lifetime. Herald/Jammer ranged weapons use Energy bolts at 18 GU/s; ordinary Lancer/Skimmer use their table speeds. Missile max travel is launch range+2 GU or 3 combat seconds, whichever first; target death loses homing and continues along last velocity. Mortar/Bombard impacts use a ground position locked at release, with velocity prediction capped 3 GU; flight is the stated duration. Invalid min-range targets cannot be attacked with mortar; default Mortar accuracy 1 means correct landing at its predicted point, not guaranteed target damage. Arc chains choose nearest detected valid next target, ID tie-break, require LOS between successive targets, never repeat a target; chains stay in launch target layer unless a particular weapon explicitly says mixed layers. All Wardens' basic weapons target both layers, subject to this chain rule.

Direct projectiles collide with tall footprints even if the structure is friendly; no friendly damage, but the shot is stopped. Exclude shooter's own footprint and its mount from that projectile's initial intersection. Spawn muzzle at the shooter's valid footprint edge toward aim; do not grant shots through a neighboring wall. Height art cannot alter this rule. Explosions use distance to target's collision boundary, ignore ordinary cover and may cross walls; direct line blasts and beams require LOS. Add an inspectable “Blocked by structure” reason. Air projectiles ignore ground bodies/low barriers but tall towers/walls still follow declared LOS; no unlisted elevation immunities.

AI reservation forecasts may be computed for every projectile, but predicted-overkill avoidance is enabled only by a listed Precision perk or Coordinated Network aura; otherwise that score feature is zero. Damage reservation is probabilistic, not a guarantee. All timed output bonuses state whether they modify per-hit damage, cooldown or continuous output; ordinary +output affects per-hit damage or DPS, not both damage and interval. Level output/interval growth is the deliberate exception applying both listed multipliers. Support output growth applies healing/repair rate and shield pool/slot sizes; no hidden percent-buff growth. Suppression Crowd Control grants its listed on-hit 2 s slow to a weapon without an existing slow, or improves its native slow by the listed percentage points; strongest-slow/boss caps still apply. Platform Guardian adds the listed bonus to mounted-tower range because Platform has no aura. Its Fortitude branch improves platform armor only.

Default target layers are G for melee, ground explosive areas, and enemy Jammer/Herald/Drainer ranged actions; Lancer and Skimmer direct weapons are B. Boss Marshal/Shatterstorm direct shots, Prism beam and Black Conductor chain are B; all other harmful boss actions are G unless their row says otherwise. No damage layer is inferred from sprite altitude. A direct projectile locks its layer; area sampling uses the declared layer and boundary-distance shape. LOS uses nearest target boundary, excludes the target’s own footprint, and does not exclude intervening allies. Mounted towers block incoming shots normally.

Stealth reveal removes concealment only; it does not grant global perception. Homing Skyguard missiles update only while the target is currently perceived; on contact loss they continue toward the last observed aim point, then along last velocity until hit/expiry. Contact regained before expiry resumes turning subject to the same 180°/second cap. Arrival warnings and damaging telegraph areas are public signals even when a caster is concealed; warning captions identify known zone/direction and duration, not hidden caster coordinates/HP. No attack may hide its necessary warning behind stealth or Reduced Effects.

#### 24A.1. Deterministic arithmetic, clocks and randomness

Positions, radii, distances used in rules, body/shield values and outputs use signed integer 1/1024 units; health/output are nonnegative. Store velocities as fixed units per second with signed fractional carry per axis; distribute movement over 60 ticks without rounding every step to zero. `round` is nearest with ties away from zero (positive half-up); floor/ceil have their mathematical meanings. Ratios/modifiers use exact rationals and checked wide intermediates; fixed-point conversion occurs after each documented output/range derivation, after each armor/shield/body transaction, and after final position advancement. Damage mitigation is one rational expression rounded once, not repeatedly per factor. Continuous pulse carry is retained per source/action/recipient and cleared when that action ends; no deferred damage after channel cancellation. Currency/XP semantics remain §25.

Lengths use integer square-root with nearest fixed-unit rounding, squared distances for comparisons where possible. Use a pinned 65,536-heading lookup table for trigonometry (0=north, clockwise); its integer sine/cosine entries use scale 2^20 and are bundled content. Angular aim/turn limits are converted to heading increments with carry. No authoritative `Math.random`, system time, renderer delta, locale sort, asynchronous worker completion order or engine physics. Tie order is score descending, legal distance ascending, simulation ID ascending unless a contract names another key. Persistent asset IDs are mapped to run IDs by bytewise UUID order; enemies are assigned by compiled packet and within-packet index; child IDs derive from parent ID and fixed child ordinal. Physical UUID generation never consumes combat RNG.

PRNG algorithm: xorshift32, unsigned state; each draw applies x ^= x<<13, x ^= x>>>17, x ^= x<<5 with uint32 wrapping. Seed each independently named stream from SHA-256 of UTF-8 canonical input `RB1|seed|stream|version`; first four digest bytes interpreted big-endian, replace zero by 0x6D2B79F5. Streams: composition, faction, rank, entrance, pressure, placement, accuracy; cosmetic uses its own stream excluded from authoritative hash. Weighted selection has integer weights, total W≤2^32; use one uint32 draw and exact floor(draw×W/2^32) for the pinned baseline mapping. AI ties consume no RNG. Accuracy consumes three draws per successfully released accuracy-based projectile: hit roll, miss angle, miss radius, even for a hit; effective probability is rational against the uint32 range. Miss angle uses the heading table and radius uniform over fixed distances [1,2] GU, added to locked intended aim point. Misses may strike another enemy by real collision. Inherently unmissable attacks consume none. Cosmetic toggles cannot change authoritative draw counts.

Plans serialize canonical JSON (sorted object keys, ordered arrays, integers, ASCII IDs, normalized decimal counters); identity is SHA-256 over all logical plan fields excluding its own ID and presentation labels. Replay identity additionally hashes normalized deployment/asset stats/tactics/health/charges, simulation version and policy version. A result hash excludes camera, captions, audio, wall time, speed preference, cosmetic RNG and UUID allocation metadata. Persist stream states/next IDs in exact block checkpoints. An archive includes its compiled plan; a generator version alone is insufficient to replay a missing plan after algorithms change.

Attack interval: after level/perk/buff factors, intervalTicks=max(1,round(60×seconds)). WarmupTicks=max(1,round(60×warmupSeconds)); positive durations also round once to at least one tick. A repeat warmup may begin before cooldown expiry so release is at max(lastRelease+intervalTicks, warmupCompletion); warmup is not an extra interval tax. First release needs a full warmup. Start/retain warmup only while detected, legal range/layer/LOS and facing within 8°. Losing eligibility resets warmup and releases reservations; existing cooldown does not disappear. A target-valid held release at projectile cap retries without restarting warmup or consuming cooldown. Sustained beam warmup occurs once per lock; 0.1-second damage pulses are fixed and level interval growth does not accelerate beam DPS a second time. First periodic output occurs after one full pulse interval, never a free pulse at start.

A direct-projectile release group (primary plus mandatory same-release secondary) reserves all needed projectile slots atomically. A delayed burst reserves only the current shot; next shots remain queued. Queue order is original due tick, owner ID, action sequence. A stalled burst cannot begin another burst or ordinary shot concurrently. Death cancels owner-dependent future shots; independent already-released explosions retain events. Hostile victory checks include independent hazards even if no projectile object remains. A warmup that is cancelled before first release consumes no active cooldown; after any first burst release cooldown is spent. Telegraphed fixed-position attacks keep their locked point after target death/contact loss; targeted buffs, heals, homing launch and contact attacks must revalidate the recipient at release. No invisible retargeting of a warned area.

Damage order inside phase 7: base current per-hit output → documented outgoing percentage effects and Q sampled at release → AoE falloff/pierce attenuation → Aegis redirect → ordered shield pools → body mitigation → clamp actual body loss to remaining health. Flat shred/on-hit statuses are installed after that impact’s damage, usable by later ordered impacts. Reduction/vulnerability/shred/slow caps apply after combining eligible modifiers as strongest-only, not before comparison. Armor additions sum, then strongest shred subtracts, then penetration clamps 0–1 and applies. Accuracy additive bonuses clamp to [0,1] last; range has no undocumented global cap. Shield hits use raw pre-body damage and ignore body resistance/cover/vulnerability. Aegis redirect is direct-projectile only. Burning bypasses front-only pools; any other applicable pool remains.

Burn stack key is source entity + activation ID. First contact creates one 10-DPS stack unless its action states another value; repeated contact from that activation refreshes only its own duration. At the three-stack cap refresh the oldest-expiring existing stack from the same source; if none, replace the lowest DPS stack only when the new one is at least as strong, expiry then source-ID ties. Tick all accepted stacks at 0.25 seconds with source attribution. Root on an already rooted target refreshes end no later than original root start plus that target’s 2/0.5-second cap; no chain reset. Ending root grants 4-second immunity. Suppression duration growth applies before the root duration cap. Fields update every 15 ticks; expiration/exit tails follow their specific rules.

Shield refresh from the same named temporary effect replaces its pool with max(remaining,new amount), capped at that effect’s current maximum; renew duration, never add duplicate copies. Distinct explicitly compatible categories absorb under §24B. Prevention attribution uses the actual would-be body loss without the protecting effect, capped at available recipient body health, credited once in absorption order; a shield absorbing raw damage overstates body prevention against armor unless converted this way. Shield and body damage displays stay separate.

Body death in phase 7 is terminal for that tick. Resolve all resulting deaths in phase 8 to a fixed point, including Platform collapse, before healing. Platform structural damage is not mitigated, not shield-absorbed and not hostile kill contribution. Support cannot revive a secondary death. HP threshold events are observed in damage order, latched once, then eligible living-owner actions schedule for the next tick. Same-tick source death cancels unreleased signatures; already-released independent effects remain.

### 24B. Shields, healing, jamming and displacement

Shield absorption order: earliest-expiring temporary ability shield, personal front shield if attack arrives inside its arc, personal omnidirectional reserve, then assigned projector shield. Within the same category use earliest expiry then source ID. Shield pools absorb sequentially; their capacities never multiply incoming damage. Shields take raw hit damage before body armor; residual passes through body mitigation. All existing shields allow overflow. AoE uses the direction from explosion center for front-shield checks; Burn ignores front arc but still hits omnidirectional shields. Shield amount, coverage and source are inspectable.

Shield Projector starts with one shared reserve pool of 1000 and can assign up to four 250-point slots simultaneously. Actual live slot totals plus unassigned reserve never exceed its pool maximum. Eligible recipients must be alive, in range and line of sight. Assign Core, selected Warden, then lowest health ratio and ID; only one projector owns a recipient slot, strongest slot max first and ID on tie. If the projector/recipient moves out of eligibility or is jammed/destroyed, unspent slot points return to the pool while those recipients lose the slot. Spent points do not return. Replenish missing pool points at 25/s after 4 s without shield damage; refill assigned slots in priority order before unassigned reserve. Level/enhancement/profile bonuses scale pool and slot maxima together. Its 6★ Core shield is separate temporary ability shielding, not four extra slots. No repeated leaving/reentering range creates new shield points.

Aegis takes 20% of eligible direct incoming raw damage into its own reserve first, capped at remaining reserve; the remainder follows recipient shield/body rules. Cannot redirect its own hit or another Aegis redirect. Strongest one applies; Core eligible. Reserve depletion redirects only points actually absorbed, not a free permanent 20% reduction. Recharge waits 4 s after last personal or redirected damage; pool recharges at its listed rate. Friendly shields reset full at a new ordinary siege or next checkpointed Endurance block; body damage persists. A temporary shield expires without damaging body, does not count as prevented damage merely for expiring, and cannot be repaired by Engineers.

Healing/repair selection uses the highest score missingHealthFraction×importance (Core 1.5 for mechanical repair, Warden 1.3, barrier 1.1, other 1), then distance, then ID. Missing durability must be ≥20 to start; an existing channel may finish the remaining <20. Ordinary Repair/Medical/Engineer/Medic/Drone Bay share a maximum of two external channels per recipient; additional channels choose another recipient. Refrain/Barracks regeneration is separate. Effects never heal a zero-health entity. XP credits actual missing-health restoration once per contributing channel, not gross rate or hypothetical output. Mender allows one enemy-heal channel per recipient and cannot heal itself. Surrender never refunds damage.

Jamming only affects tagged support structures: Repair, Medical, Detection, Shield Projector, Fabricator, Uplink, Relay, Barracks, Drone Bay, Command Node and Platform's mounted bonus. It does not stop tower weapons, personal shields, collision or earned stats. Duration refreshes to max existing/new endTick; overlapping jammers do not sum durations. Jam recovery perks reduce duration on application, minimum 1 s. A suppressed shield slot returns unspent points; no healing or reserve regeneration while projector jammed. Nullifier suppression multiplicatively reduces the stated hostile healing/regen/buff output and does not turn off ordinary weapons or boss phase logic.

No existing ordinary attack causes stun or knockback. Root prevents voluntary movement, not facing/fire/healing. Dash moves along a collision-tested path at up to 5 GU per 0.3 s; Bulwark Interpose uses the same dash duration. Boss charges move at 5 GU/s for at most 5 GU, stop at solid collision, damage each contacted target once per charge. Holdfast halves charge-induced displacement only if an attack actually defines displacement; it does not invent knockback. Gravity Snare affects air movement but never converts air collision to ground.

Support decisions reserve one of the recipient’s two channel slots in stable decision order, with an expected next-pulse restoration amount. Score missing health after already-reserved restoration; do not reserve a zero-useful-output channel. Release reservation immediately on cancellation/death/range invalidity; expire stale reservations after the next decision tick. Sources may heal/repair themselves only if biological/mechanical eligibility permits; Mender explicitly cannot. A finalized/rejected/skipped sequence≤watermark can never issue rewards again after Restore Previous. Run counter allocation must not roll back; allow only one active campaign run, eliminating out-of-order unresolved run gaps. Save/export includes run allocation/finalization watermarks and pending receipt; import validates that next sequence exceeds every included finalized/allocated sequence. Replacing an existing same-ID campaign cannot lower its local no-repeat fence. Campaign/mastery/discovery first-clear flags are fixed-size content sets and their no-repeat fence is preserved across rollback. For generated Expedition first-success bonuses, keep at most4096 successful plan identities per campaign; once full, ordinary rewards continue but further new-plan first-success bonuses stop, with clear wording. Never prune bonus claims and repay them. The claim ledger is bounded without blocking ordinary play. Import remains a replaceable user backup without competitive cheat guarantees.

Sequence/index counters are unsigned 64-bit decimal strings (maximum 20 digits). Before sequence exhaustion, atomically start a fresh UUID lineage namespace with sequence 1 and preserve campaign progress, finite first-claims and generated-bonus saturation status. Keep the two latest retired namespace fences; backups from older retired namespaces are identified as historical branches and may only import into a separately confirmed replacement slot, never merge receipts with the current lineage. Restore Previous within the active lineage preserves its local watermark. No claim of infinite unique IDs or cross-device anti-cheat follows from this practical bounded scheme. Long Watch index rolls to a new displayed epoch at its bound, preserving the modulo-3 boss schedule and saturated lifetime aggregates; this is not series completion. Only one current series is retained; Close Series stores aggregate records then frees its offer set.

Long Watch Next Sortie is the next attempt ordinal, allocated only at successful preflight. Result (win/defeat/surrender) finalizes that ordinal and advances it once; Retry uses a new run/ordinal with the same plan and no fresh first-clear entitlement. Restart after interruption retains ordinal/run/checkpoint. Reroll/preview/parking do not increment. Every third ordinal offers the boss recipe before selection; choices contain the same boss requirement and may vary legal accompanying recipes. Difficulty/band/tier changes invalidate only unstarted offers and explicitly compile replacements with new code/hash; they never modify archived plans. Watch only uses mastery reward/boss profile after Campaign Complete when explicitly selected. Tier access remains Rank 100. Calibration restrictions are clamped to min(chosen allowance,campaign’s unlocked allowance), so a Rank 30 clone cannot obtain Rank 100 command capacity or locked enemies.

An encounter-code export contains all noncampaign generator inputs including declaredRank, pressure/recipe/faction/front selection policy, attempt, population profile, versions, mode, seed, boss, difficulty, tier and modifiers; omitted user choices use explicit stored defaults. Seed alone is not a replay identifier. Anti-repeat history can influence offered seed/recipe selection but never compilation of an existing full code. Save code plus compiled hash, and reject any regenerated mismatch. The recent-plan heuristic cannot cause identical full inputs to compile differently.

### 28F. Verification before declaring open-ended play complete

Run at least1000 generated endgame plans through legality/coverage validation, including every recipe, faction, boss, tier and modifier pair. This validates generator constraints, not win rates. Separately run maxed reference builds for balanced combined arms, armor-focused, anti-air, mobile-heavy, trap-heavy and support-heavy configurations; record win rates, damage and population holds. Proposed tuning goal on tier0 Standard generated mastery: at least one viable reasonable build per recipe, while a specialist has materially different performance against its favorable and unfavorable recipes. No one fixed build should trivially dominate every highest-tier recipe. Treat these as test goals, not achieved results or mathematical guarantees.

Test50 consecutive Long Watch sorties, parking/reloading between them, interrupted/failed result commits, checkpoint restart, defeat/retry, same-offer replay, changing difficulty and all-maxed XP. Stress history compaction/claim-watermark behavior with100000 synthetic completed records, verify constant bounded collections, export validity and no duplicate first-clear payouts after restore. Check wallets at bounds, next-index persistence and tier budget overflow. Then obtain human play feedback on forecast usefulness, whether changing layout changes outcomes and whether recent plans feel repetitive. Successful legality checks alone cannot establish endless enjoyment. If play tests show maxed builds trivialize every tier, revise declared challenge profiles with measured evidence before release; do not add hidden scaling during play.

## 29. Codex handoff, consolidation and production discipline

This blueprint is the sole authoritative product specification. At implementation time inspect the current README and repository configuration, preserve useful setup and valid work, and build the specified game. No historical source is required.

### 29A. One authoritative implementation specification

Normalize this blueprint into implementation modules: core requirements, combat rules, data catalogs, UI/input, economy/progression, persistence, presentation, encounter generation/modes and verification. Do not implement multiple formulas for the same behavior. Map every requirement to a data ID, code subsystem and acceptance check. Ordinary low-risk implementation details may be chosen with documented reasoning when this specification does not prescribe them; do not invent a new gameplay system to fill a missing field.

Create a dependency graph and one prioritized task queue. Keep an invariant document for no manual combat control, no music-derived gameplay, no extra currencies, bounded entity/storage counts and durable/idempotent progression. Implement source catalogs as typed data with automated schema validation and generated reference tables; maintain a single source of truth for numbers. Separate measured balance changes from engineering refactors; seeded fixtures make outcomes comparable.

### 29B. Justified improvement policy

Codex is authorized to fix bugs, missing validation, inaccessible controls, contradictory formulas, ineffective specified perks, asset-pipeline defects and demonstrated performance problems. It should improve implementation/design where appropriate, relevant and consistent with the user's goal. Every nontrivial design change records: observed problem, requirement affected, proposed change, reason, before/after values, save/archive impact and actual validation. Test the current behavior or construct a reproducible failure before changing a working system when feasible. No arbitrary renaming, roster removal, scope expansion, replacement visual style or endless rebalancing after checks pass.

Preserve user-established constraints. For an uncertain material creative choice, present a concrete comparison/prototype to the user at the relevant milestone, while continuing independent work. Reversible routine choices do not require repeated approval. Never hide a simplified feature behind its finished name. An unimplemented ability, empty results graph or decorative Save button remains marked Designed/Blocked, not complete.

### 29C. Incremental build-and-polish loop

Read the whole design to understand dependencies; implement one coherent small subsystem at a time. For each: identify data and edge cases → implement simulation/transactions → create actual interface and necessary original art/audio → exercise it in a playable integration → inspect logs/screenshots/listening output → fix failures → verify affected regressions → checkpoint → update status → move on. Do not generate the entire roster, campaign and menus in a single shallow scaffold.

Move visual style proof into Gate1, before mass asset production. Include polished Core/terrain/Sentry/Rifle/Runner/barrier samples at actual mobile scale. Add initial original music/SFX during Gate2 so audio unlocking/mixing/captions are tested early. Gate7 completes and audits presentation across the full roster; it is not the first time real art/audio exists. Temporary diagnostics may be geometric; a milestone advertised as visually representative must use coherent raster art. Early playable scope is a milestone, not cancellation of the final scope.

At each milestone deliver the working preview if hosting permits, concise implemented changes, actual checks, known failures and next step. Prefer actual accessible URL over an instruction to run development commands on Android. A preview available only inside the development environment is explicitly labeled as such. Commit/durable-checkpoint frequently, including original editable asset sources and reproducible audio definitions. Keep no indispensable state solely in temporary scratch.
